# ModelAudit

Independent validation with leakage, calibration, drift and subgroup diagnostics.

Independently evaluate a claimed binary risk model and generate a review decision that can reject impressive but invalid results.

## Implemented

- Validate a JSON evidence bundle without executing a pickled model.
- Check feature availability relative to prediction time, overlapping row identifiers and temporal boundaries.
- Flag exact feature duplication for review.
- Compare discrimination and Brier score against a training-prevalence baseline.
- Evaluate expected calibration error and subgroup discrimination/TPR support.
- KS drift checks with BH multiple-testing adjustment and an effect-size threshold.
- Produce machine-readable findings and an executive Markdown memo.

## Run

Python 3.12 recommended. From this repository root:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
$env:OPENBLAS_NUM_THREADS='1'
$env:OMP_NUM_THREADS='2'
python -m modelaudit.cli --output reports
python -m pytest -q
```

On macOS/Linux, activate with `source .venv/bin/activate` and use `export OPENBLAS_NUM_THREADS=1`. Installing the package also provides the `modelaudit` command. Run `python -m modelaudit.cli --help` for options. No cloud credentials, paid services, external downloads or websites are required.

## Design and evaluation

The healthy fixture is a chronological split of a synthetic binary task with legitimate predictors. The flawed fixture adds the future label as a predictor and uses a random split despite a future-deployment protocol. Logistic regression can achieve near-perfect AUC in the flawed fixture, but metadata-driven leakage checks reject it. Supplied scores are evaluated without fitting or modifying the submitted model. Thresholds are explicit illustrative review policies, not externally mandated standards.

## Results

`healthy_audit.json` and `flawed_audit.json` contain findings, metrics and decisions. Each has a Markdown memo and the exact synthetic input evidence bundle. The input schema is demonstrated in `healthy_input.json`.

Reports are generated by real local algorithm runs over **explicitly synthetic data**. They demonstrate methodology, not claimed company results. Seeds are fixed. Re-run on your machine; floating point, timings and dependency versions may differ. See [methodology](docs/methodology.md) and the generated reports for measured results. CI configuration is included; no remote CI execution is claimed.

## Repository structure

- `src/modelaudit/core.py`: reusable algorithms and simulator.
- `src/modelaudit/cli.py`: repeatable experiment and report generation.
- `tests/`: meaningful invariants, failure cases and baseline checks.
- `reports/`: committed evidence from the seeded demo.
- `docs/`: assumptions, evaluation protocol and extension ideas.

## Limitations

Metadata must be accurate; static checks cannot discover all hidden leakage or certify independence. High AUC and duplicate feature vectors are warnings, not proof of leakage. Temporal overlap is a failure for this future-deployment contract; other intended-use contracts may require different splits. Subgroup gaps are descriptive diagnostics, not legal findings or proof of unfairness. This prototype does not validate calibration uncertainty, labels, causal claims, security or regulatory compliance. PASS_WITHIN_SCOPE never means universally safe.

## Audit another evidence bundle

```powershell
python -m modelaudit.cli --input reports/healthy_input.json --output reports/review
```

The bundle has `features` metadata and `train`/`test` blocks containing numerical `x`, binary `y`, numeric `time`, unique `row_id` and `group`; `test` additionally contains probability `scores`. `available_offset` is relative to prediction time: positive means unavailable at prediction. Inputs are JSON data, never executable model files.
